# ADR 0001. Технологічний стек і відхилення від ТЗ

- **Статус:** прийнято
- **Дата:** 2026-11-25

## Контекст

Технічне завдання описує інформаційну систему «Громадський бюджет» у промисловому варіанті розгортання:
контейнери (Docker), кеш і черги (Redis), об'єктне сховище файлів (MinIO), справжні BankID і Дія.Підпис,
поштовий сервер (SMTP), WebSocket для оновлення результатів.

Водночас система створюється як курсова робота з дисципліни «Технології розроблення програмного забезпечення», і стек має:

- спиратися на матеріал лекцій 7–8: ADO.NET (з'єднаний і від'єднаний сценарії), Entity Framework (Database First),
  шаблон DAL, LINQ з лямбда-виразами, посторінковий перегляд `OFFSET … FETCH NEXT`;
- використовувати вже спроєктовану й здану БД `CivicBudget` (20 таблиць, уявлення, тригери, процедури) без змін схеми;
- запускатися на ноутбуці розробника (Windows, SQL Server Express) і стабільно працювати на захисті.

Приклади в лекціях — на WinForms, але ТЗ затверджено як веб-застосунок.

## Рішення

| Частина | Рішення |
|---|---|
| СКБД | MS SQL Server 2022 Express; бізнес-правила — у БД (тригери `TR_Vote_CheckRules`, `TR_Project_StatusChange`, процедури `usp_SubmitProject`, `usp_SelectWinners`) |
| Доступ до даних | окрема бібліотека `CivicBudget.DAL`: EF Core 8 (Database First, `Scaffold-DbContext`) + репозиторії з інтерфейсами; виклики процедур і журнал аудиту — ADO.NET (`SqlCommand`, `SqlDataReader`, `SqlDataAdapter` → `DataTable` → `DataView`) |
| Бекенд | ASP.NET Core 8 Web API, REST/JSON, Swagger (OpenAPI 3); JWT (access 15 хв, refresh 7 днів), BCrypt, RBAC через `AppRole`/`UserRole` |
| Фронтенд | React 18 + TypeScript 5 + Vite, Ant Design 5, Leaflet + OpenStreetMap, Recharts, i18next (UA/EN) |
| Реальний час | SignalR замість «сирого» WebSocket: той самий транспорт, але з автоматичним перепідключенням і групою подій |
| Файли | локальна папка `uploads/` замість MinIO; у БД — метадані (`Attachment.StorageKey`) |
| Пошта | імітація: листи записуються файлами `.eml` у `mail-outbox/` фоновою службою за таблицею `Notification` |
| BankID / Дія.Підпис | імітація: «банк» повертає тестові дані особи; перевірка міста й віку виконується за полями `UserAccount` |
| Кеш, обмеження частоти | у пам'яті процесу (`IMemoryCache`, вбудований `RateLimiter`) замість Redis |
| Розгортання | без Docker: `reset.bat` (БД) і `start.bat` (бекенд + фронтенд), HTTPS через dev-сертифікат ASP.NET Core |
| Секрети | `dotnet user-secrets` / змінні середовища; у `appsettings.json` — лише заглушки |

## Наслідки

**Позитивні**

- У коді видно всі техніки лекцій 7–8: Database First, DAL, LINQ (методи й синтаксис запитів), ADO.NET в обох сценаріях.
- Правила голосування й подання перевіряє БД; застосунок їх не дублює, а перекладає `SqlException` 50001–50020 у зрозумілі повідомлення.
- Увесь стенд піднімається на одному комп'ютері без зовнішніх сервісів.

**Негативні / обмеження**

- Один екземпляр бекенду: лічильник невдалих входів, коди 2FA й обмеження частоти зберігаються в пам'яті й скидаються після перезапуску.
- Файли вкладень лежать на диску сервера — для кількох екземплярів знадобиться об'єктне сховище.
- BankID, Дія.Підпис і e-mail лише імітуються.

**Шлях до промислового варіанта** (аркуш змін до ТЗ): Docker-образи бекенду й фронтенду, MinIO для `uploads/`,
Redis для кешу та rate limiting, SMTP-клієнт замість `MailOutbox`, інтеграція з BankID / Дія.Підпис через їхні API,
CI з тестами й лінтерами.
